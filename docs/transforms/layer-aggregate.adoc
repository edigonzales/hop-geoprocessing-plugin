[[layer-aggregate]]
= Layer Aggregate
:plugin-id: LAYER_AGGREGATE_TRANSFORM
:plugin-type: transform
:description: One geometry stream and optional grouping fields.

[[layer-aggregate-description]]
== Description

`Layer Aggregate` computes one geometry result per whole layer or per group.

[[layer-aggregate-input]]
== Input

One geometry stream and optional grouping fields. The complete layer/group is buffered; the output contains only grouping fields and the aggregate geometry.

[[layer-aggregate-options]]

Controls are enabled or shown according to the selected operation/representation; inactive

[[layer-aggregate-output]]
== Output

One row per group containing grouping fields and the configured aggregate geometry; without grouping, one row for the whole layer.

[[layer-aggregate-supported-engines]]
== Supported engines

Apache Hop 2.19.0 local pipeline engine, Java 21 or 25. The installed examples run with
the local engine. Distributed engines have not been validated by this repository.

[[layer-aggregate-error-handling]]
== Error handling

Invalid configuration or geometry processing errors stop the transform and pipeline. Validate mappings before running. Use the pipeline log to identify the operation and failing input.

[[layer-aggregate-limitations]]
== Limitations

Memory depends on the largest layer/group. coverage_union requires a valid polygon coverage.

Full list: <<reference-matrix-layer-aggregate,Reference Matrix>>

[[layer-aggregate-important-parameters]]
=== Important Parameters

* `geometryFieldName`
** geometry field to aggregate
* `groupFieldNames`
** optional grouping fields; without them the full layer becomes one working set
* `operation`
** one of `dissolve`, `unary++_++union`, `coverage++_++union`, or `collect`

[[layer-aggregate-common-pitfalls]]
=== Common Pitfalls

* Memory demand is driven by the largest group.
* Without grouping fields, the full layer becomes one working set.
* `coverage++_++union` requires polygon coverages with valid shared boundaries.
