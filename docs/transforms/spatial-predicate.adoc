[[spatial-predicate]]
= Spatial Predicate
:plugin-id: SPATIAL_PREDICATE_TRANSFORM
:plugin-type: transform
:description: A primary stream and one secondary info stream.

[[spatial-predicate-description]]
== Description

`Spatial Predicate` compares a primary row against a cached secondary layer and returns either a
boolean, a filter decision, or an inner join.

[[spatial-predicate-input]]
== Input

Connect the primary producer to Spatial Predicate with a regular input hop.
In Hop 2.19, start a hop on Spatial Predicate and finish it on the secondary producer.
Choose *Secondary layer* in the hop menu. Although you start the gesture on Spatial Predicate,
the data flows from the secondary producer into Spatial Predicate. If you already drew a
regular hop from the secondary producer, remove it before creating the info hop.

The info hop tells Hop to supply a separate layer for comparison. The dialog displays the
connected producer in the read-only *Secondary info transform* field. Each geometry selector
lists fields from its own stream. Use Select Values upstream to convert WKT to native Geometry
if needed.

The following example shows the dialog with *Within* and `KEEP_MATCHED` selected.
`[v]` marks a dropdown. Distance controls appear only for distance predicates;
the boolean output field and join prefix appear only in their respective result modes.

For points within polygons, connect Points as the primary input and Polygons as the
secondary layer. Choose *Within*, the point and polygon geometry fields, and
`KEEP_MATCHED`. A point at (1, 1) matches a square from (0, 0) to (3, 3);
a point at (5, 5) is filtered out.

[[spatial-predicate-output]]
== Output

BOOLEAN_COLUMN appends a boolean. KEEP_MATCHED and KEEP_UNMATCHED filter rows and optionally route the opposite result to a reject target. INNER_JOIN emits one row per match.

[[spatial-predicate-supported-engines]]
== Supported engines

Apache Hop 2.19.0 local pipeline engine, Java 21 or 25. The installed examples run with
the local engine. Distributed engines have not been validated by this repository.

[[spatial-predicate-error-handling]]
== Error handling

If the info hop is missing or disabled, the dialog asks you to connect the secondary producer
using the *Secondary layer* info hop. A pipeline without a secondary assignment stops with
`Secondary layer info stream is not connected`. Enable or recreate the info hop and check
both field mappings before running. Predicate filter rejects are normal routing, separate
from data errors.

[[spatial-predicate-limitations]]
== Limitations

The secondary layer must fit in memory. INNER_JOIN is unsupported for disjoint and distance_gte.

[[spatial-predicate-operations-in-this-family]]
=== Operations in This Family

* topological predicates: `intersects`, `contains`, `within`, `touches`, `crosses`, `overlaps`, `disjoint`
* distance predicates: `distance++_++lte`, `distance++_++gte`

Full list: <<reference-matrix-spatial-predicate,Reference Matrix>>

[[spatial-predicate-important-parameters]]
=== Important Parameters

* `primaryGeometryFieldName`
** geometry field from the primary input
* `secondaryGeometryFieldName`
** geometry field from the secondary info stream
* `resultMode`
** controls whether the output is a boolean column, a filter, or an inner join
* optional reject target hop
** `KEEP++_++MATCHED` and `KEEP++_++UNMATCHED` can send the opposite filter result to a second output stream
* `distance`
** threshold for `distance++_++lte` and `distance++_++gte`
* `BOOLEAN++_++COLUMN`
** writes `true/false` to a new column
* `KEEP++_++MATCHED`
** keeps matched primary rows
* `KEEP++_++UNMATCHED`
** keeps unmatched primary rows
* `INNER++_++JOIN`
** one primary row can produce multiple output rows

[[spatial-predicate-common-pitfalls]]
=== Common Pitfalls

* The secondary layer is fully read before the first primary row is processed.
* `INNER++_++JOIN` is not supported for `disjoint` or `distance++_++gte`.
* The reject target stream is only meaningful for the filter modes `KEEP++_++MATCHED` and `KEEP++_++UNMATCHED`.
* The spatial index reduces the candidate set, but full geometry evaluation is still required.
