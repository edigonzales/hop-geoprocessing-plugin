[[layer-overlay]]
= Layer Overlay
:plugin-id: LAYER_OVERLAY_TRANSFORM
:plugin-type: transform
:description: A primary stream and a secondary info stream.

[[layer-overlay-description]]
== Description

`Layer Overlay` creates new overlay geometries from a primary layer and a cached secondary layer.

[[layer-overlay-input]]
== Input

Connect two independent producers to Layer Overlay. In the dialog, choose the secondary producer
from *Secondary info transform*, which lists enabled incoming data hops. Click *OK*
to assign the hop to the *Secondary layer* info stream. The assignment is saved with the
pipeline. To change producers, remove the old hop if it is no longer needed, connect
the new producer, and select it in the dialog.

Use native Geometry for both fields. Select Values can convert WKT upstream. Layer
Overlay requires one primary producer and one secondary INFO row set per copy of the
overlay. Hop can feed multiple copies of the same primary producer into one overlay.

[[layer-overlay-output]]
== Output

Zero or more geometry fragments with primary and secondary attributes. The configured prefix disambiguates secondary field names.

[[layer-overlay-supported-engines]]
== Supported engines

Apache Hop 2.19.0 local pipeline engine, Java 21 or 25. The installed examples run with
the local engine. Distributed engines have not been validated by this repository.

[[layer-overlay-error-handling]]
== Error handling

Invalid configuration or geometry processing errors stop the transform and pipeline. Validate mappings before running. Use the pipeline log to identify the operation and failing input.

[[layer-overlay-limitations]]
== Limitations

Secondary geometry complexity and fragment counts can dominate memory and runtime. Coordinate systems must already match.

== Detailed reference

`Layer Overlay` creates new overlay geometries from a primary layer and a cached secondary layer.

[[layer-overlay-important-parameters]]
=== Important Parameters

* `primaryGeometryFieldName`
** geometry field from the primary input
* `secondaryGeometryFieldName`
** geometry field from the secondary info stream
* `operation`
** one of `intersection`, `clip`, `erase`, or `identity`

[[layer-overlay-common-pitfalls]]
=== Common Pitfalls

* `Layer Overlay` produces new geometries, not only match/no-match results.
* The secondary layer is cached completely even if only part of it contributes to the final result.
* Complex polygons and heavy fragmentation drive runtime and memory more strongly than feature count alone.
