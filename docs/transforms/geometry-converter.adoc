[[geometry-converter]]
= Geometry Converter
:plugin-id: GEOMETRY_CONVERTER_TRANSFORM
:plugin-type: transform
:description: One stream with a geometry representation or numeric X/Y and optional Z/M fields.

[[geometry-converter-description]]
== Description

The **Geometry Converter** transform changes the representation of an existing geometry
or builds a Point from X/Y(/Z/M) fields. It is row-wise and does not reproject, buffer,
simplify or otherwise modify coordinates. All geometry parsing and writing goes through
the shared Geometry Type codec (`com.atolcd.hop.gis.geometry.codec.GeometryCodec`), not
through a private parser in the Geoprocessing plugin.

[[geometry-converter-input]]
== Input

One stream with a geometry representation or numeric X/Y and optional Z/M fields. An enabled Hop error connection is required in every error mode.

[[geometry-converter-output]]
== Output

A native geometry, text, binary value or Point ordinates. NULL remains NULL. RETURN_NULL emits a normal row; ROUTE_TO_ERROR sends the original input to the error connection.

[[geometry-converter-error-handling]]
== Error handling

An enabled Hop error connection is mandatory. FAIL stops on the first data error; RETURN_NULL emits NULL targets; ROUTE_TO_ERROR sends the unmodified row to that connection. Configuration and classloader failures are always fatal. See the detailed error table below.

[[geometry-converter-limitations]]
== Limitations

Coordinate input/output is Point-only. SRID assignment does not reproject. An outdated Geometry Type plugin without the GeoJSON codec API is rejected.

== Detailed reference

The *Geometry Converter* transform changes the representation of an existing geometry or builds a Point from X/Y(/Z/M) fields. It is row-wise and does not reproject, buffer, simplify or otherwise modify coordinates. All geometry parsing and writing goes through the shared Geometry Type codec (`com.atolcd.hop.gis.geometry.codec.GeometryCodec`), not through a private parser in the Geoprocessing plugin.

[[geometry-converter-representations]]
=== Representations

[cols=",",options="header",]
|===
|Direction |Values
|Input |`GEOMETRY`, `WKT++_++EWKT`, `WKB++_++BYTES`, `WKB++_++HEX`, `GEOJSON`, `COORDINATES`
|Output |`GEOMETRY`, `WKT`, `EWKT`, `WKB++_++BYTES`, `EWKB++_++BYTES`, `WKB++_++HEX`, `EWKB++_++HEX`, `GEOJSON`, `COORDINATES`
|===

`GEOMETRY` is the native Hop value type from the Geometry Type plugin. Binary input is raw WKB/EWKB without any Hop stream framing. Hex input is plain hexadecimal (case-insensitive, optional `0x`), not WKT.

`WKT` writes no SRID prefix. `EWKT` writes `SRID=++<++n++>++;` when a positive effective SRID is known. ISO WKB and WKT omit SRID; EWKB stores it in the root header. `COORDINATES` output never carries SRID information. `sridOmitted` in the converter summary records this case.

[[geometry-converter-geojson]]
=== GeoJSON Geometry conversion

`GEOJSON` reads and writes one Geometry object in a Hop String field. Features and
FeatureCollections belong to the Vector/Raster Feature transforms and Vector
Reader/Writer; the converter rejects these wrappers with a data error. It delegates
all JSON parsing, validation, CRS handling and writing to the shared Geometry Type
codec. The existing Geometry value's default string serialization remains EWKT.

[cols="1,3",options="header"]
|===
|Profile |Meaning
|`RFC7946` |GeoJSON RFC 7946: WGS84 longitude/latitude, no legacy `crs`.
|`LEGACY2008` |GeoJSON 2008 with supported named EPSG CRS and X/Y coordinates.
|`JSONFG10` |OGC JSON-FG 1.0.0: native CRS, supported curves and M values.
|`AUTO` |Input only: identify JSON-FG markers or legacy `crs`; otherwise RFC 7946.
|===

The input default is `AUTO`; the output default is `RFC7946`. JSON-FG coordinates
follow the formal axis order of their declared CRS. The codec maps them to/from the
native Geometry X/Y convention; for EPSG:4326 this exchanges latitude/longitude at
the JSON boundary. RFC 7946 remains longitude/latitude. No coordinates, datum,
units or heights are reprojected. Use <<geometry-reproject,Geometry Reproject>> as
an explicit pipeline step when a different horizontal CRS is required.

*Input context field* reads versioned JSON text from a String field. *Output
context field* writes the context returned by JSON decoding alongside the result.
Keep it through native processing and pass it to a later encoder to retain compound
CRS details and measure units/descriptions. A described measure or compound CRS
cannot be decoded to native output without an output context field. The context
is separate from `Geometry.userData`. Field names support Hop variables and use
the same collision/overwrite rules as the main result field. An explicitly supplied
context survives a NULL geometry. Without an input context, NULL geometry and its
context output remain NULL. For a non-NULL geometry, SRID assignment also updates the context's horizontal
CRS reference; an explicit compound vertical reference and measure metadata remain.
`CLEAR` removes the CRS reference from both geometry and context. These are label
changes only. Export still validates the chosen profile, CRS dimensions and height
reference; assigning a projected SRID cannot make coordinates valid RFC 7946.

WGS84 output requires a known appropriate CRS; assigning SRID 4326 does not
transform arbitrary coordinates. A Z value is not automatically a WGS84
ellipsoidal height. Unsupported CRS, conflicting SRIDs/context, non-finite values,
curves in ordinary GeoJSON and ordinates that the selected profile cannot express
are data errors. Linearize curves explicitly before RFC/Legacy export. JSON-FG
also has representability limits: a CircularString supports at most eleven control
points; collections do not permit every nested or curved structure of the native
type. No automatic splitting or linearization occurs.

Loss options are disabled by default. *Drop Z explicitly* and *Drop M explicitly*
remove only the selected ordinate on output; *Replace unrepresentable EMPTY with
NULL* permits JSON `null` when that EMPTY geometry has no lossless representation.
They never mutate the input Geometry. A NULL Hop input remains a NULL Hop output.
No additional rounding, repair or dateline splitting is performed. Polygon ring
orientation may be normalized on a copy for RFC output.

See https://www.rfc-editor.org/rfc/rfc7946.html[RFC 7946],
https://geojson.org/geojson-spec.html[GeoJSON 2008] and
https://docs.ogc.org/is/21-045r1/21-045r1.html[OGC JSON-FG 1.0.0].

[[geometry-converter-coordinate-input-and-output]]
=== Coordinate input and output

Coordinate input uses *one Point per row*:

* X and Y are required numeric fields.
* Z and M are optional numeric fields; leaving them blank means the ordinate is absent.
* X/Y/Z/M may be integer, number or big-number value metas.
* An all-NULL tuple produces a NULL row output.
* A partially supplied tuple, NaN or infinity is a data error.

Coordinate output is also Point-only. The selected X/Y fields are always written; Z/M are written only when configured. A NULL or non-Point geometry produces NULL target ordinates; a non-Point geometry is a data error. Extra input ordinates are allowed: a Point with Z can still be written to X/Y only.

[[geometry-converter-srid-handling]]
=== SRID handling

[cols=",",options="header",]
|===
|Mode |Behaviour
|`KEEP` |Preserve the effective SRID of the input geometry.
|`SET++_++IF++_++MISSING` |Assign the configured positive SRID when the input has no known SRID.
|`REPLACE` |Replace the root and child SRIDs with the configured positive SRID.
|`CLEAR` |Remove the SRID.
|===

SRID handling is *not* a coordinate transformation. SRID assignment performs no EPSG database lookup or reprojection. GeoJSON conversion separately resolves CRS metadata when required. The configured value must be a positive decimal integer and may use Hop variables. Inactive SRID values are not parsed.

[[geometry-converter-null-and-empty]]
=== NULL and EMPTY

The converter keeps `POINT EMPTY`, `LINESTRING EMPTY` and `POLYGON EMPTY` as empty geometries in native and supported binary output. A NULL input produces NULL output. The older `ValueMetaGeometry` conversion/Select Values path is separate and still maps `EMPTY` to NULL; that legacy contract is intentionally unchanged.

[[geometry-converter-byte-order-and-wkb-dialect]]
=== Byte order and WKB dialect

* `BIG++_++ENDIAN` and `LITTLE++_++ENDIAN` are honoured recursively for every geometry component.
* `WKB++_*++` writes ISO WKB (no SRID in the header).
* `EWKB++_*++` writes EWKB and sets the SRID flag when a positive SRID is known; an explicitly known SRID 0 is still representable in EWKB.
* Curves, Z/M and nested collections use the same shared codec options.

[[geometry-converter-fields-and-overwrite]]
=== Fields and overwrite

* A single output field is the default (`geometry`).
* Coordinate output uses `x`, `y` and optional `z`, `m` names.
* Existing target fields are replaced only with *Overwrite existing fields* enabled. Otherwise a name collision is a configuration error.
* Swapping X and Y target names is allowed with overwrite; it is not a special case.
* Inactive field mappings remain in the transform metadata so that switching format in the dialog does not erase them. They are not read or validated at runtime.

Field names and the active SRID value support Hop variables. Raw values are persisted; they are resolved once when the transform schema is compiled. Unresolved or empty resolved required variables are configuration errors.

[[geometry-converter-error-modes]]
=== Error handling

Every Geometry Converter needs an enabled Hop error connection with a target transform, regardless of the selected error mode. Without it, the pipeline reports a configuration error before the first row.

[cols=",",options="header",]
|===
|Mode |Behaviour
|`FAIL` |Stop at the first data error. This is not a completed processing run.
|`RETURN++_++NULL` |Emit the input row with all configured target values NULL and continue.
|`ROUTE++_++TO++_++ERROR` |Send the unmodified input row to the Hop error connection and continue.
|===

Configuration, plan and classloader failures are fatal in all modes. Data errors carry a stable `GC++_*++` code; the summary reports input/normal/error/null-output/SRID-omitted counts and a failure count per code.

[[geometry-converter-shared-installation]]
=== Shared installation

The transform is part of the existing Geoprocessing ZIP, not a separately installable plugin. Install the updated Geometry Type ZIP and the Geoprocessing ZIP together. The Geoprocessing ZIP does not contain a second Geometry Type or JTS runtime. If the installed Geometry Type is too old and lacks the GeoJSON codec API, startup fails with a clear upgrade message instead of falling back to a text or reflection bridge.

[[geometry-converter-installed-e2e]]
=== Installed E2E

The installed suite under `e2e/geometry-converter/` and the public JSON examples cover coordinate layouts, Select Values binary conversion, encoded output, curves, overwrite, RETURN++_++NULL, a real error hop, SortRows spilling, variable field names, EMPTY/error regressions and coordinate-output row balance. A second isolated Hop installation verifies that an outdated Geometry Type runtime without `GeometryCodec` is rejected with an upgrade error. A second negative pass retains GeometryCodec but removes its GeoJSON API and must also fail clearly.

A 100,000-point streaming smoke profile is available through `scripts/benchmark-converter.py`; it is not a hard performance gate.

See https://github.com/edigonzales/hop-geoprocessing-plugin/blob/main/e2e/geometry-converter/README.md[the installed E2E README] and https://github.com/edigonzales/hop-geoprocessing-plugin/blob/main/docs/implementation/geometry-converter-stage-e.md[Stage E].
